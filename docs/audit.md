# 审计与实施记录

审计依据：`problem/` 两份官方说明、原 README、全部 app/ui/prompts 模块。官方文件未修改，已有三 Agent、Artifact、文件存储、编排、API、UI 和 BestOf 架构保留。

初始可复现问题：

- README 声称存在的两份平台测试实际不存在；pytest 转而收集生成输出/快照，导致 `ModuleNotFoundError: src`。
- TestValidator 忽略 pytest 退出码和收集错误，覆盖率达标就通过；纯失败用例的计数解析也不完整。
- `/validate` 只检查设计、代码和测试计划，没有执行测试或覆盖率检查。
- CodeValidator 在平台进程内替换 `sys.path` / `sys.modules`，只判断 app 属性存在，没有执行应用 startup。
- TestAgent 把源代码正文放进 Prompt，与赛题上下文限制冲突；测试提示词还要求数据隔离失败时静默降级。
- 设计提示词把 FastAPI 默认输入校验写为 400，与测试提示词和框架默认 422 冲突；已统一默认 422。
- `.env.example` 设置 `LLM_STRICT=true`，无 Key 时也会失败。
- Mock 设计、代码、测试无条件使用车辆内容，通用性和离线模式说明不足。
- 批次/生成文件路径检查不足，未知批次读取会创建目录，状态/日志不是原子替换。
- 重复 run 可把失败批次误标成功；没有同批次执行互斥；失败下游重试缺少依赖检查。
- 车辆模板缺少内部车辆拦截、动态余量/配置 API、缴费园区字段与幂等性；带空格车牌可绕过重复检查；并发提交可能超过配额。
- 前端固定平台同端口，缺少同源托管；ZIP 缺安装/测试配置且包含运行缓存和数据。
- BestOf 会选取没有有效设计的零分批次。

按影响排序的实施计划（已执行）：

1. **验证 / 系统验证 20%**：独立启动检查、真实 pytest、JSON 分支覆盖率、JUnit 计数、失败/超时诊断、综合报告。
2. **代码质量 15% / 架构 20%**：路径约束、原子 JSON、依赖与状态保护、同批次执行互斥；保留 Artifact 通信，消除源代码 Prompt。
3. **完整性 20% / 自动化 15%**：平台回归、官方完整流程和打包后的两笔验收；修复已有车辆模板缺陷，增加透明通用回退。
4. **创新 5%**：一次候选修复，通过结构化失败文件反馈并保留原测试及修复前诊断。
5. **文档 / 可运行性 5%**：自动刷新的可视化流程、真实质量指标、跨平台 Python 启动和 demo 命令、实测后更新 README。

边界：验证使用子进程和临时目录，未提供 OS 沙箱；进程内锁不支持多个后台 worker；CSV 多表写入不是事务；离线模板不包含员工/管理员认证，通用记录模板不能自动满足任意领域需求。完整业务验收应检查设计、人工场景和真实 LLM 产物，不能只用覆盖率代替。
